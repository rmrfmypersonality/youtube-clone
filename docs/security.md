# Безопасность

## Модель угроз

Потенциальный злоумышленник: анонимный посетитель, обычный пользователь, пользователь со вскрытой
сессией, подозрительный загруженный файл. Администратор и сервер считаются доверенными.

## Что закрыто и как это устроено

- **404 вместо 403.** Недоступное неотличимо от несуществующего. Исключение: эндпоинты персонала (`/api/moderation`, `/api/admin`) отвечают 403 обычному пользователю и 401 анониму.
- **Скрытие модератором не открывает приватное.** Приватность проверяется раньше модерации.
- **Rate limit** считается по IP (`limit_req` в nginx). Ответ 429 содержит JSON.
- **Права на комментарии:** удалять может автор или админ; скрывает модератор.
- **Заголовки безопасности** задаются в nginx для каждого `location` через общие snippets.

## Известные ограничения

- **Нет HTTPS.** `install.sh` поднимает приложение по HTTP, `COOKIE_SECURE=false`. Для реального использования
  нужен TLS-терминатор перед nginx, `COOKIE_SECURE=true` и HSTS на нём.
- **Нет подтверждения email, сброса пароля и двухфакторной аутентификации.**
- **Rate limit по IP:** за общим NAT пользователи делят лимит; в Docker без прокси видны адреса шлюза.
- **Блокировки по аккаунту после неудачных входов нет**, только лимит запросов с IP.
- **CSP:** для стилей разрешён `'unsafe-inline'`. У `/docs` мягкая CSP с CDN Swagger UI.
- **Контейнеры работают от root.** Для воркера с ffmpeg это стоило бы убрать (отдельный пользователь, read-only файловая система).
- **Пароль администратора лежит в `.env`.** Для публичного стенда сменить после первого входа и удалить строку.
- **Загруженный контент не проверяется на нарушения автоматически**, только жалобами и модерацией.
- **Старые ссылки после смены handle** не работают, редиректов нет.
- **Зависимости** зафиксированы, но автоматического сканирования уязвимостей нет.
