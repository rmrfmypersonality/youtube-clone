# Работа с ИИ

## Инструмент и условия

Весь код написан через чат с Claude Sonnet (веб-чат, без доступа к репозиторию и без агентных
инструментов). ИИ не видел файлов проекта: я присылал ему содержимое файлов, вывод команд и трейсбеки.
Весь запуск и проверка выполнялись мной в Docker (PowerShell, Docker Desktop, позже Ubuntu 24.04 в WSL2).

## Процесс

1. В начале я дал ИИ полное задание: экраны, стек, архитектуру, модель данных, права, безопасность, план из 10 этапов.
2. На каждый этап ИИ присылал:
   - решения и компромиссы до кода;
   - код по шагам, у каждого шага точка git-коммита;
   - тесты;
   - ручную проверку и список граблей;
   - команду слияния ветки.
3. Я выполнял шаги в ветке `feat/*`, гонял тесты, проверял руками, присылал результат («всё работает» или трейсбек).
4. ИИ исправлял ошибки, после чего я коммитил и сливал ветку в `main` через `merge --no-ff`.
   

## Правила, которые держались

- Одна ветка на этап или часть этапа, Conventional Commits, один коммит на логичный шаг.
- Права только в policy-функциях, логика в сервисах, на границах только Pydantic-схемы.
- Каждый эндпоинт, меняющий данные или читающий по id, покрывается тестом на права и на чужого пользователя.
- Перед новой миграцией: `alembic check` (модель и миграция должны совпадать).
- Миграции с данными (категории, «Смотреть позже», `published_at`) пишутся руками.
- Деплой проверялся на настоящей чистой Ubuntu, а не только в dev-окружении.


## Что проверялось вручную, а не тестами

Поведение интерфейса, адаптив, работа плеера и перемотки, WSL и установка Docker из apt,
отрисовка Swagger под CSP. Для каждого этапа ИИ присылал чек-лист ручной проверки, я проходил его
и сообщал результат.
